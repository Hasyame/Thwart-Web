# Bug hunt, 2026-09-30: outcome

An external review of `origin/main` `e3b47e5` and the live site filed eight
bugs, each with a repro that asserted the bug. Every repro was run here first
and reproduced; each fix then turned it around into a regression test
(`server/bughunt_test.go`, `web/scripts/test-sync-recovery.mjs`,
`web/scripts/test-error-codes.mjs`, `web/scripts/test-achievements.mjs`).

| # | Bug | Fix | Test |
|---|-----|-----|------|
| 1 | A rate-limited rating was deleted locally | Server answers the daily cap `deferred`/`rate_limited`, never `rejected`, and counts only ratings about to be stored. The web client keeps a deferred rating dirty and resends it; it also treats an old server's `rejected`/`rate_limited` so. Messages corrected, and one added for waiting ratings | `TestRateLimitedRatingIsDeferredNotRejected`, `TestRefusedRatingsSpendNoAllowance`, test:sync-recovery |
| 2 | `cursor_too_old` was never recovered | Full resync with `resync=1`, then local rows the server had confirmed and did not return are dropped; the cursor is written only at the end, so an interrupted recovery restarts | test:sync-recovery |
| 3 | The ratings summary cache grew without limit | Capped at 10,000 entries, swept with the limiter every 10 minutes; a generation counter also closes the stale-average race (minor finding) | `TestSummaryCacheIsBoundedAndSwept`, `TestSummaryReadBeforeAWriteIsNotCached` |
| 4 | A slow BGG answer invited a duplicate post | A play that was fully sent and got no answer is `504 bgg_uncertain`; the app says to check BGG first and the retry button reads "Send again anyway" | `TestSlowBggAnswerIsReportedUncertain` |
| 5 | Signed-out devices kept their live stream | Streams carry their device; password change, recovery, revocation and account deletion end them | `TestSignedOutDevicesLoseTheirStream` |
| 6 | Login and recovery budgets were per identifier | Keyed on the account id once found (the typed text when not). Accepted trade-off: knowing both a handle and an address, one can learn they share an account | `TestLoginAndRecoveryBudgetsArePerAccount` |
| 7 | An expired or invalid confirmation link said "server error" | Messages for every code the server sends, in EN and FR; the verify page heading changes on failure | test:error-codes reads the codes from the Go source |
| 8 | `distinct_days` counted UTC days | The derivation takes `dayOf` as input and stays pure; the app passes the local day, the shared vectors keep UTC. Spec updated (`docs/spec/achievements/algorithm.md`) | test:achievements |

## Not done here

- **Android** (not modified from this repository): it deletes a rating on any
  `rejected` including `rate_limited`, marks an unknown outcome such as
  `deferred` synced (kept, never resent), and counts `distinct_days` in UTC.
  It already recovers from `cursor_too_old`.
- Minor findings left open: `already_present` breaking the cursor walk
  (performance only), one oversized record blocking every later batch, soft
  404s from nginx's prefix match, recovery not being atomic, and the missing
  `<h1>` on the nonexistent-card page.
